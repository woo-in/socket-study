# 3. 길이 헤더로 해결

## 목표

메시지 앞에 4바이트 길이 헤더를 붙여 2번의 경계 문제를 해결한다. 펌뱅킹 전문 수신의 핵심이다.

## 할 것

- 클라이언트: 본문 길이를 4바이트로 먼저 쓰고, 이어서 본문을 쓴다. 메시지 여러 개를 연달아 보낸다.
- 서버: 4바이트를 먼저 읽어 길이를 알아낸 뒤, 그 길이만큼 **다 읽을 때까지** 기다렸다가 메시지 하나로 처리한다.
- 길이 헤더를 두 방식으로 각각 해 본다.
  - 이진 정수: `DataOutputStream.writeInt` / `DataInputStream.readInt`
  - 숫자 문자열: `"0300"`처럼 ASCII 4자리

## 확인할 것

- `read(buf)`와 `readFully(buf)`는 무엇이 다른가?
- 2번에서 버퍼를 `byte[3]`으로 줄였던 상황에서도 메시지가 온전히 나오는가?
- 길이 헤더 두 방식의 장단점은? (패킷을 눈으로 볼 때, 다른 언어와 붙일 때)

- [ ] 두 가지 길이 헤더 방식을 모두 해 봤다
