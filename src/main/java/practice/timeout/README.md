# 5. 읽기 타임아웃

## 목표

타임아웃이 났다고 상대가 처리하지 않은 것은 아니라는 점을 직접 본다. 펌뱅킹에서 "타임아웃이 나면 재시도 전에 이체 결과부터 조회"하는 이유다.

## 할 것

- 서버: 요청을 받으면 "처리 완료"를 출력하고, 5초 `sleep`한 뒤 응답한다.
- 클라이언트: `setSoTimeout(3000)`을 걸고 요청을 보낸다.
- 연결 타임아웃도 따로 해 본다: 아무도 듣지 않는 주소에 `socket.connect(address, 1000)`.

## 확인할 것

- 클라이언트에서 어떤 예외가 나는가? 그때 서버 로그에는 무엇이 찍혀 있는가?
- 클라이언트가 타임아웃 뒤 같은 요청을 다시 보내면, 이체라면 무슨 일이 생기는가?
- 연결 타임아웃과 읽기 타임아웃은 각각 어떤 상황에서 나는가?

## 완료 조건

- [ ] 클라이언트는 타임아웃인데 서버는 처리를 끝낸 상황을 재현했다
- [ ] 연결 타임아웃과 읽기 타임아웃의 차이를 설명할 수 있다
