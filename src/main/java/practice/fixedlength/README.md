# 4. 고정길이 필드와 EUC-KR

## 목표

필드 이름 없이 위치로 읽는 고정길이 전문을 만들고 푼다. 소켓 없이 바이트 배열만으로 해도 된다.

## 할 것

아래 필드로 된 40바이트 전문을 만든다(인코딩 EUC-KR).

| 필드 | 길이 | 형식 | 예 |
|---|---|---|---|
| 계좌번호 | 16B | 문자, 왼쪽 정렬, 남는 자리 공백 | `1002123456789   ` |
| 금액 | 13B | 숫자, 오른쪽 정렬, 남는 자리 0 | `0000000150000` |
| 예금주명 | 11B | 문자, 왼쪽 정렬, 남는 자리 공백 | `홍길동` + 공백 5칸 |

- 값 → 40바이트 `byte[]` (조립)
- 40바이트 `byte[]` → 값 (분해)
- 조립한 결과를 다시 분해하면 원래 값이 나오는지 테스트로 확인한다.

## 확인할 것

- `"홍길동".length()`와 `"홍길동".getBytes("EUC-KR").length`는 각각 얼마인가?
- 글자 수로 공백을 채우면 전문 길이가 어떻게 틀어지는가?
- 예금주명이 11바이트를 넘으면? 한글 한 글자가 경계에서 반으로 잘리면?

## 완료 조건

- [ ] 조립 → 분해 왕복 테스트가 통과한다
- [ ] 한글이 들어가도 전문이 정확히 40바이트다
